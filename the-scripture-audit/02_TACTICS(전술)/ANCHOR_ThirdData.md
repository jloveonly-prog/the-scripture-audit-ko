## 📐 STEP 5. MATRIX 역산 (수학적 검증)

> **이 단계가 없으면 증명이 아니다 — 반드시 수식으로 완결한다.**

```
MATRIX 역산 3원칙:

원칙 1. 수식화
  → 모든 수치를 하나의 수식으로 표현한다
  → 형식: [앵커A] + [앵커B] + ... = [구절X의 값]
  → 예: 32(즉위) + 8(통치) + 2(투병) = 42 ✅

원칙 2. 양방향 검증
  → 순방향: A + B = C 성립?
  → 역방향: C - B = A 성립?
  → 양방향 모두 성립해야 확정

원칙 3. 잉여 데이터 확인
  → 수식에 포함되지 않은 성경 수치가 있으면
    그 수치도 수식과 모순이 없는지 확인
  → 모순 없음 → 판결 확정
  → 모순 있음 → TYPE-M 재발동 (새 이상 신호 포착)
```

**MATRIX 출력 형식 (표로 반드시 시각화):**

| 구절 | 데이터 | 값 | 수식 내 역할 |
|:---|:---|:---:|:---|
| 대하 21:5 | 여호람 즉위 나이 | 32 | 기준점 |
| 대하 21:20 | 여호람 통치 기간 | 8 | 누적 A |
| 대하 21:18 | 여호람 투병 기간 | 2 | 누적 B |
| **합계** | **= 아하지야 탄생 시 부친 나이** | **42** | ✅ 대하 22:2 해소 |

### STEP 2-P. 명제형 앵커 강제 확장 검색 (4차 ~ 6차)

```
━━━ 4차 검색: 명제 부정 전수 (Negation Exhaustive Search) ━━━

  → 쟁점 명제 P를 한 문장으로 확정한다.
     예) P = "아버지가 태어나셨다"
  → P를 KJV 66권 전체에서 전수 검색한다.
     질문: "P를 자구로 진술하는 구절이 몇 건 존재하는가?"
  → 동시에 대칭 검색: "P의 반대 방향을 진술하는 구절은 몇 건인가?"
  → 결과는 반드시 표로 고정한다:

     | 검색 대상 | 건수 | 대표 구절 |
     |:---|:---:|:---|
     | P를 진술하는 구절 | 0건 | (반례 없음) |
     | P의 반대 방향 구절 | 다수 | 시 2:7, 히 1:5, 히 5:5, 행 13:33 |

  🚨 필수 구분 (`01_MANDATE/IDENTITY_Scribe42.md` [METHOD] 3원칙):
     · 성경이 그 주제를 **아예 다루지 않아** 0건    → "단순 부재"   → 앵커로 쓸 수 없음
     · 성경이 그 주제를 **풍부하게 다루면서**
       한 방향만 0건                              → "저들의 침묵" → 강력한 앵커 ★
     → 이 구분을 하지 않고 0건을 곧바로 증거로 쓰면 TYPE-AG 오용이다.

  🚨 연동 의무:
     · `BVCAP_Pipeline.md` GATE 3 STEP 2.5(반례 자동탐색)를 즉시 발동한다.
       사용자가 반례를 제시할 때까지 기다리지 않는다.
     · GATE 1 ⑤(화자·장르 태그)를 부착해 표본을 분리한 뒤 집계한다.
       서로 다른 화자·장르를 한 표본에 합산 금지.


━━━ 5차 검색: 귀결 파생 후 검증 (Entailment Derivation) ━━━

  → 상대 명제 P에서 문법적·정의상 필연적으로 따라 나오는 귀결 Q를 도출한다.
  → 형식:  P + [정의상 참인 전제] → Q
  → 도출된 Q를 4차와 동일한 절차로 KJV 전수 검증한다.

     예) P = "영원하신 아버지가 여자에게서 태어났다"
         + [정의] "낳은 자는 태어난 자의 어머니다"
         → Q = "마리아는 하나님의 어머니다"
         → KJV 전수: "mother of God" 0건 (최근접 표현은 눅 1:43 "the mother of my Lord")

  ⚠️ 허수아비 방지 (TYPE-AF 입증책임):
     Q는 상대가 **동의하지 않더라도 P에서 필연적으로 따라 나와야** 한다.
     상대가 말하지도 않았고 P에서 필연적이지도 않은 것을 붙이면 허수아비 논증이다.
     → 판정 시 "전제2가 정의상 참인가"를 먼저 명시적으로 기록한다.


━━━ 6차 검색: 미인용 구절 대입 (Unquoted-Verse Substitution) ━━━

  → 상대가 **인용하지 않은** 구절 중, P를 대입하면 구문이 붕괴하는 것을 찾는다.
  → 표적 우선순위:
     ① 인칭대명사 대면 구문 — 1인칭↔2인칭 소유격 대치, 호격(Father / thou / thine)
     ② 관계 동사 구문 — 낳다·복종하다·보내다·맡기다·중보하다·증언하다
        (최소 두 항을 요구하는 비대칭 동사)
     ③ 청원·명령 구문 — 화자와 수신자가 분리되어야만 성립하는 문형
  → 각 후보 구절에 P를 대입해 문장이 여전히 의미를 이루는지 검사한다.

     예) P = "예수의 혼 = 아버지"를 행 2:27에 대입
         원문: "thou wilt not leave my soul in hell"
         대입: "당신께서 당신의 혼을 지옥에 남겨두지 아니하시리이다"
         → 2인칭 주어와 1인칭 소유격이 동일 지시 대상이 되어 청원 구문 붕괴 ✅ 앵커 확보

  🚨 이 6차가 "상대에게 전장을 고르게 해 주는" 편향을 끊는 **유일한** 단계다.
     상대가 인용한 구절만 검증하면 검증 대상 집합 = 상대가 고른 집합이 된다.
     4·5차가 아무리 잘 돌아도 6차를 건너뛰면 앵커는 상대의 울타리 안에 갇힌다.
```

### STEP 4-P. 명제형 앵커 유효성 시험 (수치형 STEP 4·5의 대응물)

> 수치형은 `[앵커값] ± [A값] = [B값]`과 MATRIX 역산으로 완결한다.
> 명제형에는 대입할 수식이 없으므로, 아래 **3중 관문**이 그 자리를 대신한다.

| 관문 | 질문 | 통과 조건 |
|:---:|:---|:---|
| ① **대입 붕괴** | P를 앵커 구절에 대입하면 구문이 의미를 잃는가? | 문법 요소(대명사 격·동사 태·접속사·호격)가 **기능을 상실**해야 통과 |
| ② **교차증인** | 앵커가 서로 다른 책/저자 2인 이상에서 나오는가? | 아래 교차증인 독립성 검증 절차 적용 |
| ③ **역가설 생존** | ¬P를 본문에 대입했을 때 결정적 내부 모순이 폭발하는가? | TYPE-AC 실행. **폭발하지 않으면 IRONCLAD 불가** |

| 관문 통과 조합 | 부여 가능한 최대 등급 |
|:---|:---:|
| ① 단독 | VIABLE |
| ① + ② | STRONG |
| ① + ② + ③ | IRONCLAD **후보** → STRESS-TEST-7 + AUTO-GRILL 의무 통과 후 확정 |

> [!CAUTION]
> **③은 등급 상한선이다.** ¬P가 내부 모순으로 죽지 않으면, 정황 증거가 아무리 두꺼워도 IRONCLAD로 올리지 않는다.
>
> **레퍼런스 케이스 (프로토콜 정상 작동)**: `05_REPORT(전과보고서)/bible_believer/REPORT_사울왕구원_유력.md` §5-A 10번 — "with me" 217례 전수조사가 STRONG급 정황을 확보했으나, TYPE-AC 역가설 대입에서 **"결정적 내부 모순 미발견"**이 나와 🟡 유력 견해에서 정지했다. 같은 문서 §6이 이 관문을 무시하고 IRONCLAD로 재격상을 시도했다가 §7에서 무효 처리되었다. (같은 사건의 다른 국면 판례: `03_WAR_LOG(전투기록)/CHRONICLE_사울의구원논쟁_*` 5건)

### 📎 부록 — 실패 유형 (이 프로토콜이 없을 때 반복되는 사고)

특정 저자·문서의 주장을 **100% 전수 검증하고도** 결정적 앵커를 놓치는 사고가 실제로 발생했다. 원인은 검증 누락이 아니라, 앵커가 **상대가 인용한 구절 집합에 갇힌 것**이다.

| 놓친 앵커의 유형 | 필요했던 단계 | 전형적 위력 |
|:---|:---:|:---:|
| 상대 명제를 자구로 진술하는 구절이 KJV 전수 0건 (반대 방향은 4개 저자에 분포) | **4차** | IRONCLAD |
| 상대 명제에서 정의상 필연적으로 따라 나오는 귀결이 KJV 전수 0건 | **5차** | STRONG |
| 상대가 인용하지 않은 구절에 명제를 대입하니 인칭 구문이 붕괴 | **6차** | STRONG |

> **교훈**: 전수 검증의 완전성(N/N)은 **검증 대상 집합의 완전성을 보장하지 않는다.** 100%를 검증해도, 그 100%가 상대가 고른 목록이면 사각지대는 그대로 남는다.
>
> 📌 이 실패 유형이 실제로 발생한 구체 사례와 산출된 앵커 3건은 **해당 감사를 수행한 엔진 쪽 문서**에 기록한다 — 이 전술 파일은 BVCAP 독립 자산이므로 외부 엔진의 산출물 경로를 참조하지 않는다.

## 🧑‍⚖️ 교차증인 독립성 검증 (Cross-Witness Independence Check) — v1.1 신설

> **발동 조건**: COMBO-VERIFY에서 TYPE 3종 이상이 수렴하여 IRONCLAD 후보가 확정된 직후, STRESS-TEST-7과는 별개로 반드시 실행한다.
> **핵심 질문**: *"수렴한 TYPE 무기들이 실제로 서로 다른 책(저자)에서 나온 독립 구절에 적용되었는가, 아니면 같은 구절 1~2개를 여러 각도로 분석한 것뿐인가?"*
> **성경적 근거**: 신 19:15, 마 18:16, 고후 13:1 — "두세 증인의 입으로 말마다 확정하라." 증인은 서로 다른 사람이어야 증언으로 성립하듯, 성경 해석의 "증인"도 서로 다른 책/저자에서 나온 독립 구절이어야 한다. TYPE 무기 3종이 전부 같은 구절에 적용된 것은 "증인 1명이 세 가지 방식으로 증언한 것"이지 "증인 3명의 증언"이 아니다.

### 실행 절차

```
[STEP 1] 수렴 TYPE별 근거 구절 목록화
  → COMBO-VERIFY에서 발동한 각 TYPE이 어느 구절에 적용되었는지 표로 정리한다.
  → | TYPE | 적용 구절 | 소속 책(저자) |

[STEP 2] 책(저자) 독립성 카운트
  → 위 표에서 서로 다른 책(저자)이 몇 개 등장하는지 센다.
  → 같은 책의 인접 구절(예: 창 3:16과 창 3:20)은 독립 증인 1개로만 카운트한다.
  → 완전히 다른 책/저자(예: 욥기 + 히브리서 + 유다서)는 각각 독립 증인으로 카운트한다.

[STEP 3] 태그 부여
  → 서로 다른 책(저자) ≥ 2개 확인 → ✅ [교차증인 ✓ — N개 독립 책/저자]
  → 서로 다른 책(저자) ≤ 1개(동일 구절/동일 저자 내부 반복) → ⚠️ [교차증인 미확인]

[STEP 4] 신학적 결정 표로 전달
  → 이 태그는 `BVCAP_GHQ.md` PHASE 5 "7. 신학적 결정" 표의 입력값으로 쓰인다.
  → [교차증인 ✓] + IRONCLAD → 확정(Doctrine)으로 표기 가능
  → [교차증인 미확인] + IRONCLAD → 내부 등급(IRONCLAD)은 그대로 유지하되, 목회 적용 등급은 개연성(Probability)으로 하향 표기 — 교리화 금지
```

## 📌 레퍼런스 케이스

```
[아하지야 난제]
  구절A: 대하 22:2 — 아하지야 즉위 시 42세
  구절B: 왕하 8:26 — 아하지야 즉위 시 22세
  충돌: 42세 vs 22세

  앵커 검색:
  → 대하 21:5  — 여호람 즉위 시 32세
  → 대하 21:20 — 여호람 8년 통치
  → 대하 21:18 — 여호람 2년 투병 후 사망  ← 제3 앵커 확보

  MATRIX 역산:
  32 + 8 + 2 = 42 ← 아하지야 탄생 시 부친 여호람의 나이
  → 22세(왕하) = 아하지야 자신의 나이
  → 42세(대하) = 왕조 기준 부친 나이 좌표
  → 모순 없음 ✅

[솔로몬 외양간 난제]
  구절A: 왕상 4:26 — 외양간 40,000칸
  구절B: 대하 9:25 — 외양간 4,000칸
  충돌: 40,000 vs 4,000

  앵커 검색:
  → 왕상 10:26 — 병거 1,400대  ← 제3 앵커 확보

  MATRIX 역산:
  1,400(병거) × 3(마리/대) = 4,200 ≈ 4,000(작전 단위) ✅
  4,000(작전 단위) × 10(개별 수용칸) = 40,000(전체 수용칸) ✅
  → 4,000 = 병거 운용 작전 단위 외양간
  → 40,000 = 개별 말 수용 칸막이 총수
  → 동일한 시설을 다른 기능 기준으로 계산한 것 ✅
```
