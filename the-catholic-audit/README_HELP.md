## Q1. 왜 Python인가? — py로 실행해야 하는 이유가 있었나?

**있었습니다. 단, 정확히 세 가지 일에만입니다.** 이 프로젝트에서 py가 맡은 일과 맡지 않은 일을 나누면 구조가 명확해집니다.

### 역할 분담 원칙: 기계 = 전수성·재현성 / LLM = 의미 판단 / 사람 = 최종 확정

| 일 | 담당 | 이유 |
|:---|:---:|:---|
| **전수 교차 스캔** (~260개 주장 × ~200개 부정 ≈ **5만+ 쌍**) | py (임베딩) | 사람도 LLM도 5만 쌍을 빠짐없이 볼 수 없다. "전수 조사했다"는 주장은 기계만 **증명 가능**하게 할 수 있다. 임베딩 스캔은 수 분, LLM으로 같은 걸 하면 후보 2,537건 심사에만 실측 ~4시간(383건 ≈ 45분) |
| **장부 정리·무결성 검사** (CSV 생성, `verify_pipeline.py` 22항목, 인용 대조) | py | 결정적(deterministic)이고 공짜로 재실행 가능해야 한다. "커버리지 100%", "환각 0건" 같은 주장을 **검증 가능한 명제**로 만드는 게 py 계층의 존재 이유 |
| **원문 수집** (`fetch_sources.py`) | py | 크롤링은 그냥 py가 정답 |
| 신학적 의미 판단 (진짜 모순인가?) | **LLM** | 임베딩은 "주제 인접"과 "논리 모순"을 구분 못 한다 — 그래서 STAGE 2가 존재 |
| 논증 작성 (OODA 공방, 쉬운 설명판) | **LLM** | 판단·서술 작업을 스크립트화하면 실패한다 — 자매 프로젝트에서 번역을 py로 자동화했다가 스텁/날조 파일이 양산된 실측 전례가 있고, 그 교훈이 이 생태계의 규칙이 됐다 |
| 경계 사례 확정, COL 카드 승격 | **사람** | 최종 책임은 자동화하지 않는다 |

### 그래서 답은

- py는 "프로그램을 py로 짜고 싶어서"가 아니라, **"전수 조사했다 / 100% 심사했다 / 인용은 전부 진짜다"라는 주장을 남이 검증할 수 있는 형태로 만들기 위해** 존재합니다. 순수 LLM 파이프라인으로도 비슷한 보고서는 나오지만, 그 주장들이 **입증 불가능한 자기 선언**이 됩니다.
- 반대로 py로 하면 안 되는 일(번역·신학 판단·논증 작성)을 py로 하려던 시도는 이 생태계에서 실제로 실패했고 스크립트가 삭제됐습니다.

## Q2. 가톨릭의 방어 방식은 무슨 철학인가? — "스토아"가 아니라 "스콜라"입니다

먼저 이름 정정: **스토아 철학(Stoicism)**은 고대 그리스의 윤리학파(제논, 세네카)로 이 문제와 무관합니다. 말씀하신 "말 바꾸기, 층위 이동으로 빠져나가는 방식"의 정체는 이름이 비슷한 **스콜라 철학(Scholasticism)**과 그 파생 기법들입니다:

| 기법 | 정체 | 작동 방식 | 본 엔진의 대응 코드 |
|:---|:---|:---|:---:|
| **구별법 (distinguo)** | 스콜라 철학의 핵심 토론 기술 (아퀴나스, 아리스토텔레스 논리학 기반) | 모순 A vs Not-A에 직면하면 "구별하겠습니다(distinguo)" — A는 의미₁에서 참, Not-A는 의미₂에서 참이라고 층위를 쪼갠다. 예: 세례의 필요성을 "수단상 필요(necessitas medii)"와 "계명상 필요(necessitas praecepti)"로 분리 | CE-10 (등급 방패) |
| **결의론 (casuistry)** | 개별 사례별 양심 판단론 — 예수회가 발전시킴 | 일반 규범을 개별 상황의 "주관적 사정"으로 완화. Amoris Laetitia의 "사목적 식별"이 전형 | CE-09 (사목적 배려 방패) |
| **교리 발전론** | 뉴먼 『그리스도교 교리 발전론』(1845) | 통시적 탈출구 — "모순이 아니라 유기적 발전이다" | CE-01 (발전 호소) |
| **권위 등급 위계** | De Fide → Sententia Certa → … → Pastoral 의 무류성 등급표 | "그 문서는 낮은 등급이라 구속력이 없다"로 충돌 자체를 무효화 | CE-10, CE-08 |
| **신비 도피** | 부정신학의 오용 | "인간 이성으로 이해 불가한 신비" 선언으로 검증 종료 | CE-05 |

역사적으로 흥미로운 점: **이 기법들을 가장 신랄하게 공격한 사람도 가톨릭 내부인**이었습니다 — 파스칼의 『시골 친구에게 보내는 편지』(1656)는 예수회 결의론을 "어떤 죄도 빠져나가게 해주는 기술"이라고 조롱한 고전입니다. 즉 "이건 무한 탈출 기술 아니냐"는 당신의 직관은 새로운 지적이 아니라 370년 된 내부 고발과 같은 계열입니다.

## Q3. "그 방식이면 누구나 뭐든 빠져나갈 수 있는 것 아닌가?" — 맞습니다. 그리고 그게 바로 이 설계의 출발점입니다

당신의 직관은 과학철학에서 **반증불가능성(unfalsifiability)** 문제라고 부르는 것과 정확히 같습니다: 사후 구별(post-hoc distinction)을 무제한 허용하는 체계는 원리상 절대 틀릴 수 없고, 절대 틀릴 수 없는 체계는 아무것도 주장하지 않는 것과 같다(포퍼).

### 성경으로 검증하면 왜 막히는가

```
우리: "성경 X절이 교리 Y와 모순된다"
상대: "그 해석 권한은 교도권에 있다. 당신의 해석은 사사로운 해석이다"
→ 게임 종료. 증거가 아니라 '해석 권위'의 문제로 전환됨.
```

외부 기준(성경)은 상대가 **해석 독점권**을 주장하는 순간 무력화됩니다. 그래서 내부 문헌 전략을 택한 것이고, 이 선택은 논리학에서 유서 깊은 정공법입니다 — **내재적 비판(immanent critique)**, 고전 논리학 용어로는 논리적 의미의 **ad hominem 논증**(인신공격이 아니라 "상대 자신의 전제로부터 논증하기"): *상대가 받아들이지 않는 전제로는 아무것도 강제할 수 없지만, 상대 자신의 문서는 상대를 구속한다.*

### 그런데 내부 문헌으로 옮겨도 구별법은 또 나온다 — 엔진이 실제로 하는 일

여기가 핵심입니다. 이 엔진은 구별법을 **금지하지 않습니다. 채점합니다.** 판정 기준은 하나입니다:

> **그 구별이 상대 자신의 문서에 근거하는가, 아니면 궁지에 몰려서 방금 발명한 것인가?**

| 구별의 근거 | 판정 | 실제 사례 |
|:---|:---:|:---|
| 구별이 **자기 문서에 이미 있음** | ⚠️ PARTIAL (방어 성립 인정) | COL-015: "묵시적 신앙" 구별은 트렌트 1547년 원문의 votum 조항 + CCC 846-848에 실재 → 검사 1승 4패로 정직하게 기록 |
| 구별의 문서적 근거가 있으나 **실천이 배반** | ⚠️ PARTIAL~강한 긴장 | COL-016: "사목적 식별" 구별은 있으나 교구별로 정반대 적용(폴란드 금지/몰타 허용) + 두비아 공식 미답변 |
| 구별이 **사후 발명**이고 자기 문서·실천과 충돌 | 💥 IMPLOSION | #13(종교 자유) Syllabus 78항 축: "이주민 공적 예배 허용"을 오류로 단죄(1864) → "공적 종교 실천 부정은 인간 위격에 대한 상해"(DH 3, 1965). v7 적대 재심리에서 **가톨릭 측 변호인(Opus 5)조차 이 축은 방어 불가를 자인** |

즉 **반증불가능성 문제에 대한 이 엔진의 답**은: 탈출 기술의 사용 자체를 막을 수는 없지만, 각 탈출 시도가 **문서에 근거했는지(ad hoc이 아닌지)를 건별로 감사**할 수는 있다는 것입니다. v9 최종 기준으로 IMPLOSION 1건(#13)은 "탈출이 문서적으로 실패한 사례", PARTIAL 23건은 "탈출이 문서적으로 성립했거나, 기소 자체의 사실 결함이 재심리에서 적발된 사례"입니다. 처음 17건이었던 IMPLOSION이 교차검증(다른 모델의 변호)을 거치며 1건까지 줄어든 과정 전체를 숨기지 않고 기록한 것 — 그것이 이 채점의 신뢰 근거입니다.

### 📝 정오 기록 (v7 재심리, 2026-08-30)
이 문서의 이전 판은 위 표의 "사후 발명" 예시로 **#12(동성 축복)**를 들었으나, v7 적대 분리 재심리에서
2021년 Responsum **원문**에 관계절("결합 그 자체"의 승인 한정)·개인 축복 허용 문장·전례적 논증 골격이
실재함이 확인되어 **그 예시는 오류였고 #12는 PARTIAL로 하향**됐다. 역설적으로 이것이 위 채점 기준이
실제로 작동한다는 최고의 증명이다 — 원문을 읽자 "발명"이 "문서화"로 재분류됐고, 엔진은 자기 주장을 낮췄다.

### 남는 한계 (정직 공시)

1. **무한 후퇴는 원리상 안 끝납니다** — "내부 문헌의 해석 권한도 교도권에 있다"는 최후 방어가 항상 가능합니다. 엔진은 이걸 부메랑 필터(F6: "그 무류한 문헌을 읽는 당신의 해석은 무류한가?")로 되받지만, 이 메타 논쟁 자체는 어떤 파이프라인도 종결시킬 수 없습니다.
2. **자기 대국(self-play) 편향** — 검사·변증·중재자가 같은 AI입니다. 편향 금지 원칙과 PARTIAL 하향 실적으로 완화했지만, 구조적 비판은 유효합니다 (개선안은 Q6).

## Q4. 그래서 이 파이프라인과 결과물은 합당한가?

**"무엇을 증명했다고 주장하느냐"를 정확히 잡으면 합당하고, 과잉 주장하면 합당하지 않습니다.**

### 이 파이프라인이 실제로 확립한 것 (검증 가능)

1. 인용은 전부 진짜다 — 74장 전수 원문 대조, 환각 0건
2. 긴장은 실재한다 — 이 22개 쟁점 중 다수는 **가톨릭 내부인들끼리 실제로 싸우는 문제**다 (두비아 추기경 4인, 피니 파문 사건, 교구별 분열 — 전부 가톨릭 사람들이다)
3. 각 방어의 강도가 **건별로 채점**되어 있다 — 그리고 방어가 이긴 기록(PARTIAL 5건, 검사 패배 라운드)이 그대로 실려 있다

### 이 파이프라인이 증명할 수 없는 것

- "가톨릭이 객관적으로 붕괴했다"는 **세계관 독립적 결론** — 최종 판단은 독자의 해석학적 전제에 달려 있고, 어떤 방법론도 이를 대신 못 합니다. 보고서가 IMPLOSION/PARTIAL을 나눠 놓은 것이 바로 이 한계의 인정입니다.

### 다른 방식으로 접근했어야 했나? — 대안 비교

| 접근 | 장점 | 치명적 단점 | 채택 여부 |
|:---|:---|:---|:---:|
| **순수 LLM** (py 없이 문헌을 통째로 넣고 "모순 찾아줘") | 단순함 | 전수성 증명 불가, 재현 불가, 실행마다 다른 결과, 감사 추적 없음 | ❌ |
| **형식 논리 인코딩** (명제를 논리식/온톨로지로 변환 후 추론기 실행) | 수학적 엄밀성 | 모델링 비용 폭발 + 싸움이 "당신의 형식화가 원문에 충실한가"로 옮겨갈 뿐 — 해석 논쟁이 사라지지 않고 이사만 감 | ❌ |
| **학술 문헌 인용** (신학계 논문으로 논증) | 권위 확보 | "권위 vs 권위" 구도 — 상대는 자기 학자를 인용하면 끝. 내재적 비판의 강제력이 사라짐 | ❌ |
| **현행: 기계 전수 스캔 + LLM 심사 + 사람 확정 + 법정 형식** | 전수성·재현성·감사추적 + 의미 판단 + 방어 강도 채점 | 복잡함, 자기 대국 편향 | ✅ |

결론: **접근 자체는 합당한 선택**입니다. 개선 여지는 접근의 교체가 아니라 구현의 정리에 있습니다(Q6).

## Q5. SVAP과 왜 달라졌나? — 비교표

"SVAP 방식으로 생각했는데 진행하다 보니 이렇게 됐다"는 느낌은 정확한 관찰입니다. 그런데 이 분화는 표류가 아니라 **두 가지 실제 차이가 강제한 결과**입니다.

| | **SVAP** (설교 감사) | **CVCAP** (가톨릭 감사) |
|:---|:---|:---|
| 감사 대상 | 설교자 **한 명**의 설교 **한 편** | 한 기관의 **2,000년 문헌 코퍼스 전체** |
| 검증 명제 수 | 설교당 주장 수십 개 — AI가 직접 전수 열람 가능 | 명제 수천 개, 쌍(pair)으로는 **5만+** — 기계 스캔 없이는 전수 불가 |
| **판정 기준 (심판)** | **성경 (외부 공유 기준)** — 설교자도 성경의 권위를 인정하므로 성립 | **내부 정합성 (A vs Not-A)** — 상대가 성경 해석 독점권을 주장하므로 외부 기준이 무력화됨 (Q3) |
| 전제 개수 | **1개** (주장 하나를 성경에 비춤) | **2개** (문헌 A와 문헌 B, 둘 다 상대의 공식 문서) |
| "왜 그럴듯하게 들리는가" 단계 | 있음 — 단일 화자의 설득력을 평가 | **없음** — 전제가 둘이라 "그럴듯함"을 물을 단일 대상이 없음 (쉬운 말 원칙이 A해설/B해설 구조로 바뀐 이유) |
| 자동화 파이프라인 | 불필요 (py 없음) | 필수 (STAGE 1~3) — **규모가 강제** |
| 판결 체계 | 주장별 BIBLICAL/UNSUPPORTED/UNBIBLICAL → 설교 종합 SOUND/CAUTION/ALERT | 항목별 IMPLOSION/PARTIAL/LOOP |
| 검증 게이트 | GATE -1(주장 추출) → BVCAP GATE 0~5 | STAGE 1(임베딩)→2(LLM)→3(원문)→사람→OODA 법정 |
| 오탐의 주 원인 | 주장 의역 왜곡 | 어휘 유사·방향 오류·동일 입장 오인 |
| 사람 개입 지점 | 판정 전체 | 경계 사례 확정 + COL 승격 심리 |

### 중요: 당신의 SVAP 직관은 버려진 게 아닙니다

생태계 설계상 **성경으로 가톨릭 교리를 심판하는 SVAP식 트랙은 그대로 살아 있습니다** — `../the-scripture-audit/05_REPORT(전과보고서)/catholic/`의 BVCAP 보고서 12편이 그것입니다(교황 수위권, 마리아 교리, 화체설 등). CVCAP은 그걸 **대체**한 게 아니라, 상대가 "해석 권위" 카드로 그 트랙을 무력화할 때를 대비한 **제2전선**입니다. 같은 교리가 양쪽 트랙 모두에서 무너지면 통합 단계에서 🔴 CHECKMATE를 선언하는 이중 트랙 구조입니다(`CVCAP_GHQ.md` 분리 선언 참조).

```
교리 X ──→ 성경 법정 (BVCAP, SVAP식·외부 기준) ──→ ❌ CONTRADICTION ─┐
      └──→ 문헌 법정 (CVCAP, 내부 정합성)      ──→ 💥 IMPLOSION ────┴→ 🔴 CHECKMATE
```

### 최소 핵심 (이것만 있으면 파이프라인이 성립)

```
fetch_sources.py      원문 수집          ┐
conflict_detector.py  STAGE 1 탐지       │ 4개 스크립트
llm_judge.py          STAGE 2 심사       │ + 무결성 검사 1개
verify_citations.py   STAGE 3 원문 대조   ┘
verify_pipeline.py    자가 점검 (22항목)
```

나머지는 부가물입니다: `run_cvcap_combos.py`(키워드 정규식 태깅 — 사실상 장식, 문서 스스로 "확정 수치 아님" 공시), `generate_graph.py`(구버전 시각화), 각종 md 문서 계층.

### 프로그래머 관점의 실제 군살 (정직한 자가 비판)

| 문제 | 현황 |
|:---|:---|
| 데이터가 코드에 박혀 있음 | `conflict_detector.py`의 수작업 제외 목록 46쌍이 하드코딩 — 별도 데이터 파일로 빼야 함 |
| 카드 저장 형식 이원화 | `batch*.md`(여러 장 묶음)와 개별 카드 파일이 혼재, ID 표기도 `CCC-0847`/`CCC-846_848` 혼용 |
| 경로 하드코딩 | 스크립트마다 `D:\01.TheScriptureAudit_ko\...` 절대 경로 — 설정 파일로 뽑아야 함 |
| 보고서 버전 잔재 | v2~v6가 전부 남아 있음 (이력 보존 가치는 있으나 혼란 요인 — README에 "v6만 보라" 안내로 완화) |
| 자기 대국 편향 | 검사/변증/중재자를 **서로 다른 모델**로 분리 실행하면 구조적 비판을 크게 완화 가능 — 미구현 |
| 문서 계층 3중 | GHQ/Pipeline/Methodology 3문서 체계는 처음 온 사람에게 과함 — README의 순서도가 이를 완화하기 위한 장치 |

### 다시 만든다면 (권고 우선순위)

1. 제외 목록·경로·모델 ID를 `config.yaml` 하나로 추출
2. 카드 저장을 개별 파일 + 엄격한 ID 스키마로 통일 (batch 파일 해체)
3. OODA 법정을 검사·변증에 **서로 다른 모델** 배정 (adversarial split)
4. `run_cvcap_combos.py` 삭제 또는 STAGE 1에 흡수
5. 하나의 CLI 엔트리포인트 (`python -m cvcap run-all`)
